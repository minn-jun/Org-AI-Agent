# memory_seed_20200504

20200504 과제(Low Vision Smart Glass) 전용 STM/MTM 시드다.

`memory_seed/`는 5개 가상 과제로 만든 기존 세트이고 회귀 테스트용으로 그대로 둔다.
이 폴더는 **실제 과제 문서를 LTM으로 쓰는 구성**에서 그 위에 얹을 STM/MTM이다.

## Tier 구성

| Tier | 내용 | 출처 |
|---|---|---|
| STM | 2021-12-20 ~ 12-30의 회의 요약, 통화 메모, 지시, action item, 일일 요약 | 이 폴더 `stm/` |
| MTM | 2021-09-01 ~ 12-29의 회의록, 초안, 검토 보고, 주간 보고 | 이 폴더 `mtm/` |
| LTM | 과제 공식 문서 883건 | `RAG/export/knowledge_service_core_tech_20200504/` |

## 업무 줄기

실제 코퍼스의 2단계 폴더 구성을 따라 여러 갈래를 함께 넣었다.
한 과제지만 서로 다른 흐름이 병렬로 도는 구조라, 계층 검색이 주제까지 갈라야 한다.

```
기술개발   웹 서비스 화면 설계 · 시각 유형별 UI/UX · 훈련 서비스 플랫폼
H/W        HMD 기구 디자인 · 마이크로디스플레이 모듈 · 시험평가
연구비     예산 소진 계획 · 세목 변경 · 이월 · 현물부담 · 퇴직급여충당금
인력       외부연구원 참여 · 신규 채용 · 협약 변경
IP         선행특허 조사 · 특허 출원 · 학술대회 논문
사업화     MOU 13건 · 시범 서비스 · 사업화 추진 체계
보고       연차보고서 · 주간 보고
```

`ltm/` 폴더는 비워 둔다. LTM은 파일이 아니라 `org_agent_mvp/ltm_corpus.py`가
`chunks.jsonl`을 역색인으로 읽어서 채운다.

파일로 떨구지 않는 이유는 세 가지다.

| 문제 | 수치 |
|---|---|
| 길이 편향 | STM/MTM 중앙값 436자 vs 과제 문서 중앙값 2,158자, 최대 2,019,319자 |
| 파일명 충돌 | 883문서 중 79개 이름이 중복(166건). `ev_ltm_{stem}`이 깨진다 |
| 채점 비용 | 문서 단위 선형 스캔이 질의당 2.4초 |

청크 단위로 채점하고(평균 754자, STM/MTM과 자릿수가 같다) 근거는 문서 단위로 접는다.
근거 id는 `ev_ltm_{doc_id}`이고 doc_id는 상대경로 sha1 앞 16자라 고유하다.
역색인을 쓰면 질의당 17ms다.

## 시점

**2021년 12월 30일**을 "오늘"로 잡았다.
2단계 1차년도 마감 직전이라 연차보고서 작성, 연구비 이월, 세목 변경이 동시에 걸려 있다.
STM/MTM/LTM이 한 질문 안에서 같이 필요해지는 구간이라 계층 혼합 검색을 시험하기 좋다.

## 사실관계

실제 코퍼스에서 뽑은 값이다.

- 과제명 시야확보 주변위험 보조 및 잔존시력의 정보인지 능력 발달을 가능케 하는
  Low Vision Smart Glass 서비스 개발 (20012260)
- 기간 2020.07.01 ~ 2022.12.31, 1단계 BM 개발 / 2단계 기술개발
- 주관 가천대학교 산학협력단 / 참여기업 ㈜피씨티 / 특허조사 태창특허법률사무소
- 2단계 1차년도 정부출연금 443,750천원, 2차년도 556,000천원
- 1단계 평가 계속, 78.6점
- 역할 분담: 가천대는 시기능 훈련 서비스 플랫폼과 시각 유형별 UI/UX,
  피씨티는 증강현실 글래스 H/W와 펌웨어

**등장인물은 전부 가상이다.** 실제 코퍼스의 개인 이름은 쓰지 않았다.
기관명만 실제 값이다.

## 계층 간 긴장 지점

평가셋을 만들 때 쓰라고 일부러 심어 둔 것들이다.
STM/MTM만으로는 답이 안 나오고 LTM을 봐야 풀린다.

| # | 내용 | 필요한 계층 |
|---|---|---|
| 1 | 내부 초안 목표일(2021-12-27)과 협약상 공식 제출 기한이 다르다 | STM + LTM |
| 2 | 이월 금액이 1차년도 정부출연금 443,750천원 대비 허용 범위인지 | MTM + LTM |
| 3 | 성능지표 2개 항목 미달 판단이 공식 목표치 기준과 맞는지 | MTM + LTM |
| 4 | 인건비→연구활동비 세목 변경이 허용 범위인지 | STM + LTM |
| 5 | 원격 교육 모듈 2차년도 이관이 연차별 개발 내용과 맞는지 | MTM + LTM |
| 6 | 관리자 화면 2차년도 연기가 연차별 개발 내용과 맞는지 | MTM + LTM |
| 7 | 디자인 컨설팅비 4,500,000원을 어느 세목으로 처리하는지 | MTM + LTM |
| 8 | 외부연구원 참여 불가 사유가 공통운영요령의 어느 조항인지 | MTM + LTM |
| 9 | MOU 13건과 논문·학술대회가 정량 성과 목표에 어떻게 계상되는지 | MTM + LTM |
| 10 | 특허 출원 전 학술대회 공개가 지식재산권 지침상 가능한지 | STM + LTM |
| 11 | 퇴직급여충당금이 이월 대상 잔액 계산에 포함되는지 | STM + LTM |
| 12 | 시험평가 측정 조건이 계획서의 평가 방법과 일치하는지 | STM + LTM |

### 한 갈래로 이어지는 사슬

여러 문서를 순서대로 밟아야 풀리는 것도 넣었다.
단일 문서 검색으로는 안 되고 계층을 오가며 이어 붙여야 한다.

```
외부연구원 참여 검토 (MTM 11-03)
    → 참여 불가 결정 (MTM 12-01)
        → 신규 채용 전환 (STM 12-22 / MTM 12-22)
            → 인건비 집행 불가
                → 이월 신청 사유 (MTM 12-21 / STM 12-29)
                    → 이월 한도와 절차는 LTM
```

```
연구활동비 부족 (MTM 11-29)
    → 특허 용역비 정산으로 잔액 마이너스 (STM 12-26)
        → 디자인 컨설팅비 12-31 지급 기한 (MTM 12-13 / STM 12-21)
            → 세목 변경 우선순위 상향 (STM 12-23)
                → 세목 변경 처리 (STM 12-29)
```

각 항목의 STM/MTM 쪽 문서는 **공식 기준을 단정하지 않고 "확인이 필요하다"로 남겨 뒀다.**
LTM을 안 보면 답할 수 없게 만든 것이다.

## 사용

환경변수 두 개로 붙인다.

```bash
MEMORY_ROOT=memory_seed_20200504 LTM_CORPUS=auto python -m org_agent_mvp
```

- `MEMORY_ROOT` — STM/MTM 시드 폴더. 기본값은 `memory_seed`
- `LTM_CORPUS` — `chunks.jsonl` 경로. `auto`면 `../RAG/export/...`에서 찾는다.
  주지 않으면 `ltm/` 폴더만 LTM으로 쓴다(기존 동작).

둘 다 안 주면 기존 `memory_seed` 세트가 그대로 돌아간다. 회귀 테스트는 영향받지 않는다.
